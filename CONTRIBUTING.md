# Як долучитися

Дякуємо, що хочеш зробити студію кращою! Коротко про те, як ми працюємо.

## Перед початком

- Прочитай [`ARCHITECTURE.md`](ARCHITECTURE.md) — це контракт проєкту (правила, пакети, граф
  імпортів, як тестувати). Інтерфейс — [`GUI.md`](GUI.md) і [`DESIGN.md`](DESIGN.md).
- Велику зміну спершу опиши в issue: що й навіщо — так простіше домовитися до того, як написано код.

## Правила коду

- Go 1.27, модуль `ytcartell`. На Windows збираємо з `CGO_ENABLED=0`.
- Нових залежностей не додаємо без вагомої причини (напиши в PR, чому без неї ніяк).
- Коментарі в коді — англійською; усе, що бачить користувач, — українською, простими словами, на «ти».
- Мережа — лише з `context.Context`; UI-горутина ніколи не блокується (див. ARCHITECTURE.md).
- **Жодних справжніх ключів, токенів, особистих шляхів чи ідентифікаторів** — ні в коді, ні в тестах,
  ні в скриншотах. У тестах — явно вигадані значення (`sk-test-…`, `demo-…`).
- Тести ходять лише на локальні mock-сервери (`httptest`), ніколи на справжні сервіси.

## Перед pull request

```sh
gofmt -l .                       # має бути порожньо
CGO_ENABLED=0 go build ./...
CGO_ENABLED=0 go vet ./...
CGO_ENABLED=0 go test ./...
```

Змінив екран — подивись його PNG: `GUISHOTS=<папка> go test ./internal/appui/<екран> -run TestShots`
або `go run ./cmd/guishots -only <назва>`; додай скриншот до PR.

Опиши в PR, що змінилось для користувача, і як ти це перевірив. Надсилаючи код, ти погоджуєшся, що
він поширюється на умовах [MIT](LICENSE).
